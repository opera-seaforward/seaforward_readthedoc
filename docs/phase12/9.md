Because a climatology is built **once** and reused, rivers are simpler than tides. The
driver `run_forecast_cycle.sh` has a `--rivers` flag that, each cycle, just **copies** the
pre-built `croco_runoff.nc` into the run folder (the same way it copies the grid). It does
not regenerate anything.

You run, for example:

```bash
./run_forecast_cycle.sh --tides --rivers        # parent, tides + rivers
```

The flag also selects the right pre-built binary (`croco_plain_tides_rivers`). See the
companion chapter for the full list of flag combinations.

**Runs stay in separate folders.** The output folder name carries the same tags as the
binary, so a run *with* rivers and a run *without* land in different places and never
overwrite each other:

```
model-runs/IGOG_12/20260726_plain_tides/          # --tides           (no rivers)
model-runs/IGOG_12/20260726_plain_tides_rivers/   # --tides --rivers  (with rivers)
```

This makes a clean **river vs no-river comparison** easy — run the same date both ways
and compare the two `croco_his.nc` files. Any difference in coastal salinity is purely
the rivers:

```bash
./run_forecast_cycle.sh --tides --rivers --date 2026-07-26   # with rivers
./run_forecast_cycle.sh --tides          --date 2026-07-26   # without rivers
```
