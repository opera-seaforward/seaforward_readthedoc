Now we turn `river_list.txt` into `croco_runoff.nc`, the file CROCO reads. The builder
must be run **from the `prepro` folder** (so it can find its helper modules).

```bash
conda activate seaforward
cd ~/seaforward/sftools/croco_pytools/prepro
python make_river_run.py \
    --input_dir ~/seaforward/forecast/scratch/IGOG_12/CROCO_FILES/DAI_RIVERS/ \
    --croco_dir ~/seaforward/forecast/scratch/IGOG_12/CROCO_FILES/ \
    --Yorig 2000 --Ystart 2000 --Mstart 1 --Yend 2000 --Mend 12 \
    --rivers_cyl 365.25 --file_format FULL
```

The backslashes `\` at the end of lines let one command span several lines — type it all,
or put it on one line without the `\`.

Argument meanings:

- `--input_dir` — the `DAI_RIVERS/` folder from Step 1,
- `--croco_dir` — where your grid is and where the output goes,
- `--Yorig 2000` — the model's year origin (must match your CROCO setup),
- `--rivers_cyl 365.25` — **the important one**: makes the file a repeating yearly cycle
  (a climatology). Without it, the forecast could not read the right day each year.

When it finishes it prints something like:

```
make_river_run: wrote .../croco_runoff.nc (cycle=365.25, 7 rivers) + for_croco_in.txt
```

Two files are now in your `CROCO_FILES/`:

- **`croco_runoff.nc`** — the river forcing CROCO will read,
- **`for_croco_in.txt`** — the text block you will paste into `croco.in` (Step 4).

**Check the runoff file looks right:**

```bash
cd ~/seaforward/forecast/scratch/IGOG_12/CROCO_FILES
ncdump -h croco_runoff.nc | grep -E "n_qbar|cycle_length"
```

You want to see `n_qbar = 7` (7 rivers) and `cycle_length = 365.25` (the yearly cycle).
