Now we turn `river_list.txt` into `croco_runoff.nc`, the file CROCO reads. The builder
must be run **from the `prepro` folder**, so it can find its helper modules.

```bash
conda activate seaforward
cd ~/seaforward/sftools/croco_pytools/prepro
python make_river_run.py \
    --input_dir ~/seaforward/forecast/scratch/IGOG_12/CROCO_FILES/DAI_RIVERS/ \
    --croco_dir ~/seaforward/forecast/scratch/IGOG_12/CROCO_FILES/ \
    --Yorig 2000 --Ystart 2000 --Mstart 1 --Yend 2000 --Mend 12 \
    --rivers_cyl 365.25 --file_format FULL
```

The backslashes let one command span several lines. Type it all, or put it on one line
without them.

The arguments:

- `--input_dir` — the `DAI_RIVERS/` folder from Step 1
- `--croco_dir` — where your grid is, and where the output goes
- `--Yorig 2000` — the model's year origin, which must match your CROCO setup
- `--rivers_cyl 365.25` — **the important one**: makes the file a repeating yearly
  cycle. Without it the forecast could not find the right day in a later year.

When it finishes:

```text
make_river_run: wrote .../croco_runoff.nc (cycle=365.25, 7 rivers) + for_croco_in.txt
```

Two files are now in `CROCO_FILES/`:

- **`croco_runoff.nc`** — the river forcing CROCO reads
- **`for_croco_in.txt`** — the text block you paste into `croco.in` in Step 4

**Check the runoff file:**

```bash
cd ~/seaforward/forecast/scratch/IGOG_12/CROCO_FILES
ncdump -h croco_runoff.nc | grep -E "n_qbar|cycle_length"
python3 -c "
import xarray as xr
d = xr.open_dataset('croco_runoff.nc')
print([str(n) for n in d.runoff_name.values])
"
```

```text
n_qbar = 7 ;
qbar_time:cycle_length = 365.25 ;
['Niger.txt', 'Ogoou.txt', 'Sanaga.txt', 'Kouilou.txt', 'Nyanga.txt', 'Nyong.txt', 'Wouri.txt']
```

`cycle_length = 365.25` confirms the yearly cycle. **Compare the names against Step 1's
list**: seven here, ten there. Congo, Cross and Niari were dropped because their mouths
sit outside the grid, as Step 1 explains. If a river you need is missing, that is where
to look.
