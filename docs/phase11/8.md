Before wiring rivers into the automatic system, run a short test. The config has been
edited in place, so you can launch it directly:

```bash
cd ~/seaforward/forecast/scratch/Canary_12
conda deactivate
source ~/seaforward/env.sh
nohup ./croco croco.in > run_rivers.log 2>&1 &
tail -f run_rivers.log
```

Or let the driver assemble it, which handles the atmosphere and the dates for you —
`--rivers` is covered further on in this chapter.

The line that proves the rivers are being read:

```bash
grep -m3 "GET_PSOURCE" run_rivers.log
```

```text
GET_PSOURCE -- Read Run-off flow fields      for time =    189.5
GET_PSOURCE -- Read Run-off flow fields      for time =    190.5
GET_PSOURCE -- Read Run-off flow fields      for time =    191.5
```

CROCO opened `croco_runoff.nc` and found what it expected. Those times are **days into
the climatology's yearly cycle**, not model days — day 189 is early July, matching the
cycle date. They advance one per day as the run proceeds.

If the step table then keeps printing finite numbers — kinetic energy steady, `trd = 0`,
no `NaN` — the rivers are running stably. The run ends with `MAIN: DONE`, one per grid:

```bash
grep -c "MAIN: DONE" run_rivers.log      # 1 without a nest, 2 with one
```

A second check is the salinity itself. The river should be visibly freshening the water
near its mouth:

```bash
cd ~/seaforward
python3 -c "
import xarray as xr, numpy as np
d = xr.open_dataset('forecast/scratch/Canary_12/CROCO_FILES/croco_his.nc',
                    decode_times=False)
s = d.salt.isel(time=-1, s_rho=-1).where(d.mask_rho == 1)
print('surface salinity: min %.2f  max %.2f  mean %.2f'
      % (float(s.min()), float(s.max()), float(s.mean())))
"
```

```text
surface salinity: min 31.68  max 37.00  mean 36.20
```

The domain mean is 36.2, which is the ambient value for this coast, and the minimum is
**31.68** — four and a half units fresher, at the Senegal's mouth. That gap is the
river doing its job.

If the minimum sits at the ambient value instead, nothing is being injected: check the
`psource_ncfile` block's indices against the ones the builder reported in Step 2, and
check `PSOURCE` really is defined in the binary you ran.
